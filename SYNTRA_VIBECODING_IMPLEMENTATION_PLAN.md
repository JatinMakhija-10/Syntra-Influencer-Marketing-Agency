# Syntra — Complete Vibecoding Implementation Blueprint

**Purpose:** A practical, phase-by-phase build plan for creating Syntra's production-ready website with Google Antigravity and deploying it on a modern web stack.

**Brand direction:** Dark Luxury Cyber-Editorial & High-Tech Motion Studio  
**Visual source of truth:** `UI_UX_DESIGN_SYSTEM.md` supplied with the project  
**Recommended implementation:** Next.js App Router + TypeScript + Tailwind CSS + CSS variables + lightweight native motion  
**Data source:** Google Sheets via a public-safe Google Apps Script endpoint, accessed through a same-origin server route  
**Default theme:** Dark  
**Primary visual tokens:** `#080808` obsidian and `#FFD100` golden yellow

---

# 0. The Core Strategy

Do not ask Antigravity to generate the entire site in one instruction. A single huge prompt tends to create one of three outcomes: a polished hero with unfinished sections, decorative UI that does not work, or a large component file that is difficult to maintain.

Use an **inspect → plan → implement → run → inspect in browser → fix → commit** loop. The agent should work in small, reviewable phases, verify the running application, and stop at each acceptance gate rather than claiming completion because the code compiles.

## Product goals

1. Present Syntra as a premium, motion-first creative editing studio and creator-agency network.
2. Explain the studio and its services quickly, then provide enough detail to help a prospective client make contact.
3. Showcase real work through a project/portfolio layer with video, image, social, and website previews.
4. Display an approved, public subset of the creator CRM with usable search and filters.
5. Provide working contact routes, form validation, clear success/error states, and useful fallback contact methods.
6. Maintain fast, responsive, accessible behavior across mobile, tablet, and desktop.
7. Preserve the exact brand tokens and interaction direction in the supplied design specification.

## Non-goals for the first release

- Do not build a complete private CRM or creator-management dashboard.
- Do not allow public visitors to edit creator information.
- Do not expose internal outreach data, private creator emails, deal values, notes, or negotiation status.
- Do not add elaborate WebGL/3D effects before the core page is stable.
- Do not invent client testimonials, project results, statistics, or logos to fill empty sections.
- Do not add payment processing, login, or a CMS unless it becomes a separately scoped requirement.

## Critical source-content decisions to resolve before launch

The supplied design spec has a content conflict: the hero metric says **“2023 Founded”**, while the About section says **“Founded: 2025.”** Choose the verified year once and define it in a single content constant. Do not show both values.

The source spec also lists “150+ Projects,” “60+ Happy Clients,” “5 Countries,” and “100% Delivery Rate.” Treat these as claims that need confirmation. Keep a central content file where they can be edited or hidden. If a claim cannot be substantiated, omit it or replace it with a verified measure.

The footer currently says `© 2025 Syntra`. Use a dynamic current year unless the design owner has an explicit reason to freeze it.

# 1. Recommended Stack and Project Architecture

## 1.1 Stack

Use the current stable scaffold generated by the official Next.js initializer. This plan deliberately keeps most styling in standard CSS variables so that it remains portable if the generated Tailwind version differs from the version assumed in an old config snippet.

- **Framework:** Next.js App Router
- **Language:** TypeScript, strict mode
- **Styling:** Tailwind CSS for layout utilities plus CSS variables for the token system and complex effects
- **Fonts:** Syne for display text and Inter for body/UI text
- **Icons:** `lucide-react` for simple interface icons; avoid icon spam
- **Animation:** CSS transitions, keyframes, `IntersectionObserver`, and a small number of state-driven transitions. Add a motion library only if a real interaction requires it.
- **Theme:** `data-theme="dark" | "light"` on the root HTML element; persist the user's choice
- **Creator data:** Google Sheets → Apps Script → Next.js route handler → typed React components
- **Contact:** A real form provider/server endpoint or direct Email/WhatsApp links. Never simulate a successful submission without sending the message.
- **Deployment:** Vercel is the straightforward fit for a Next.js app; Netlify is also possible with its compatible Next.js support.

### Why this stack

The site has a marketing/portfolio experience, a server-side data proxy, and possibly a contact form. Next.js handles all three without forcing the browser to call the Apps Script endpoint directly. CSS variables keep the brand system independent from utility-class conventions. Native CSS is sufficient for the requested hover, reveal, shimmer, marquee, and theme transitions.

## 1.2 Initial setup commands

Run these commands in the terminal inside Antigravity. If the project directory already exists, inspect it first instead of creating a second app inside it.

```bash
npx create-next-app@latest syntra-web --typescript --tailwind --eslint --app --src-dir --import-alias "@/*"
cd syntra-web
npm install lucide-react
npm run dev
```

If the scaffold asks setup questions, choose the App Router, TypeScript, Tailwind, ESLint, a `src/` directory, and the `@/*` import alias. Let the generator select compatible package versions. Do not combine Tailwind v3 configuration syntax with a Tailwind v4 project; first inspect which version was installed.

## 1.4 Data and UI boundaries

- `src/data/*` contains editorial content and verified static site details.
- `src/lib/*` contains validation and external-data logic, not visual JSX.
- `src/types/*` contains shared data contracts.
- `src/components/ui/*` contains reusable visual primitives.
- `src/components/sections/*` contains complete page sections.
- `src/app/api/*` contains server-side integration endpoints.

The website should still render its core content if the creator endpoint fails. Creator data is a supplemental section, not a reason for the entire page to crash.

# 2. Design System Implementation

The design system must be implemented before the detailed page sections. If the token system is right, components can be refined consistently. If the tokens are wrong, every section becomes a one-off patch.

## 2.1 Brand identity

- Brand: **Syntra**
- Positioning: motion-first creative editing studio and creator-agency network
- Eyebrow: `Editing-first creative studio`
- Hero: `We craft stories` / `that convert.`
- About: `A creative studio shaping digital experiences — frame by frame.`
- Visual character: premium, cinematic, confident, experimental, editorial
- Avoid: generic agency-template styling, bright rainbow gradients, excessive pills, stock dashboard cards, constant animation, tiny low-contrast text, and randomly mixed corner radii

## 2.3 Typography

Load Syne and Inter using the framework's supported font optimization where available. Avoid adding multiple competing font families.

| Role | Family | Size | Weight | Line height | Tracking |
|---|---|---:|---:|---:|---:|
| Hero H1 | Syne | `clamp(2.8rem, 7vw, 6rem)` | 700–800 | `1.05` | `-0.025em` |
| Section H2 | Syne | `clamp(1.875rem, 4vw, 2.5rem)` | 700 | `1.15` | `-0.02em` |
| Card titles | Syne | `1.125rem–1.5rem` | 600–700 | `1.25` | normal |
| Stat values | Syne | `clamp(2.5rem, 6vw, 5rem)` | 800 | `1.0` | normal |
| Eyebrows | Inter | `10px` | 600 | `1.2` | `0.30em` |
| Badges | Inter | `10px` | 600 | `1.2` | `0.20em` |
| Navigation | Inter | `11px` | 600–700 | `1.2` | `0.18em–0.25em` |
| Body | Inter | `14px–16px` | 300–400 | `1.65` | normal |
| Captions | Inter | `12px` | 400 | `1.5` | normal |

Use `clamp()` to make type responsive. Body copy should remain legible on phones; do not force all text into the tiny all-caps label style.

## 2.4 Layout rhythm

Use a consistent spacing scale rather than arbitrary per-element numbers:

- `--space-1: 4px`
- `--space-2: 8px`
- `--space-3: 12px`
- `--space-4: 16px`
- `--space-6: 24px`
- `--space-8: 32px`
- `--space-10: 40px`
- `--space-12: 48px`
- `--space-16: 64px`
- `--space-20: 80px`
- `--space-24: 96px`

Page content should use a consistent maximum width around `1200px–1320px`, with fluid side padding (`clamp(20px, 5vw, 72px)`). Section vertical padding should scale with viewport size, roughly `80px–140px`, and compress on small screens.

Use a deliberate radius vocabulary: `12px` for fields/small surfaces, `16px` for buttons and compact panels, `20px` for bento cards, `28px–32px` for feature surfaces, and `9999px` only for pills/circles. Avoid a different radius on every component.

## 2.5 Surface effects

- **Ambient glows:** low-opacity radial gradients, fixed behind content, `pointer-events: none`, hidden from assistive technology.
- **Glass:** use `backdrop-filter: blur(20px)` only where the background meaningfully shows through; include a solid/translucent fallback.
- **Borders:** mostly one-pixel hairlines. Let spacing and contrast establish hierarchy instead of heavy outlines.
- **Grain:** optional subtle overlay, never strong enough to reduce text legibility. Keep it static; do not animate noise across the whole page.
- **Bento cards:** dark/light surface token, one-pixel border, `20px` radius, `translateY(-3px)` hover lift, subtle yellow border/glow.
- **Primary CTA:** yellow background, `#080808` text, high contrast, restrained shimmer on hover only.

Do not apply blur to every element. Too much glassmorphism makes the site look foggy and can hurt performance.

## 2.6 Motion tokens

```css
:root {
  --ease-brand: cubic-bezier(0.22, 0.9, 0.18, 1);
  --duration-fast: 300ms;
  --duration-medium: 500ms;
  --duration-theme: 350ms;
  --section-space: clamp(5rem, 10vw, 8.75rem);
}
```

Motion rules:

1. Buttons and links: about `300ms`.
2. Card and modal transitions: about `350–500ms`.
3. Scroll reveals: start at `opacity: 0; transform: translateY(14px)`; end at `opacity: 1; transform: translateY(0)`.
4. Use `IntersectionObserver` to trigger reveals once, and disconnect observers when no longer needed.
5. Marquee: `35s linear infinite`, with duplicate content, hover pause, and edge fade. The track must be truly seamless.
6. Stats: count up only on first viewport entry, not every scroll bounce.
7. Avoid animating large blur radii, complex filters, or layout dimensions continuously.
8. Honor `prefers-reduced-motion: reduce`: disable or nearly eliminate movement, turn off looping marquee motion, and show final states immediately.
9. Never make essential content visible only after JavaScript animation succeeds.

## 2.7 Required global CSS primitives

Create these reusable classes/utilities early:

- `.page-shell` — shared page width and gutters
- `.section` — section vertical spacing
- `.eyebrow` / `.pill-label` — small uppercase metadata
- `.section-heading` — repeated section title pattern
- `.bento-card` — standard card surface and hover behavior
- `.btn-primary` / `.btn-secondary` — consistent CTAs
- `.btn-shimmer` — yellow primary action with restrained shimmer
- `.glass-panel` — blur/translucent panel with fallback
- `.reveal` / `.is-visible` — reveal state
- `.sr-only` — accessible visually hidden label
- `.focus-ring` — visible keyboard-focus treatment

Do not scatter slightly different versions of these classes across separate sections.

# 3. Site Map, User Flow, and Section Order

## 3.1 Recommended homepage structure

1. Sticky header
2. Hero
3. Service marquee
4. About / positioning
5. Services overview and category tabs
6. Selected work / portfolio
7. Creator network (only if creator acquisition and brand discovery are intended public use cases)
8. Process
9. Verified stats
10. Team/founder
11. Testimonials (approved and real only)
12. Contact form and social contact cards
13. Footer

If the homepage becomes too long, keep a compact Creator Network preview on the homepage and create `/creators` for full filtering/search. If the site is mostly a studio sales site, the creator directory should not overpower portfolio work.

## 3.2 Navigation behavior

Desktop nav anchors: About, Services, Testimonials, Process, Contact. A Portfolio or Creators link can be added if those sections are important. Keep the header to the most useful destinations; no more than about five primary nav items plus a CTA.

- Header fixed/sticky at `64px` height.
- Background follows the theme with translucent surface and `backdrop-filter: blur(24px)`.
- Anchor clicks should scroll smoothly unless reduced motion is active.
- Offset anchor targets so the fixed header does not cover section headings (`scroll-margin-top`).
- The mobile menu must open, close, close on navigation, close on Escape, and restore focus sensibly.
- Ensure the menu cannot trap the page in an unscrollable state if it uses an overlay.

## 3.3 User journey

**Client journey:** Understand the studio → inspect service categories → judge quality through portfolio/testimonials → understand process → submit an enquiry or open WhatsApp/email.

**Brand/creator journey:** Open creator directory → search or filter by niche/language → compare creator audience/median views/view ratio → open approved public profile or public rate card → contact Syntra to discuss a campaign.

Avoid forcing these two journeys into the same giant form. Use clear, distinct CTAs such as `Start a project` and `Discuss a creator campaign`.

### 7.3 Apps Script endpoint

Create a bound Apps Script project for the spreadsheet. Use the `Website Creators` tab as the endpoint source. The following code intentionally emits only approved public fields.

```javascript
function doGet() {
  const sheet = SpreadsheetApp.getActiveSpreadsheet().getSheetByName('Website Creators');
  if (!sheet) {
    return jsonOutput_({ error: 'Missing Website Creators sheet', data: [] });
  }

  const values = sheet.getDataRange().getValues();
  if (values.length < 2) {
    return jsonOutput_({ data: [], updatedAt: new Date().toISOString() });
  }

  const headers = values[0].map((value) => normalizeHeader_(value));
  const index = {};
  headers.forEach((header, i) => { index[header] = i; });

  const required = [
    'id', 'name', 'url', 'niche', 'language',
    'followers', 'medianviews', 'published'
  ];
  const missing = required.filter((header) => index[header] === undefined);
  if (missing.length) {
    return jsonOutput_({ error: 'Missing required columns', missing, data: [] });
  }

  const creators = values.slice(1)
    .filter((row) => isTrue_(row[index.published]))
    .map((row) => {
      const id = String(row[index.id] || '').trim();
      const name = String(row[index.name] || '').trim();
      const url = safeHttpsUrl_(row[index.url]);
      const niche = String(row[index.niche] || 'Other').trim();
      const language = String(row[index.language] || '').trim();
      const followers = numberOrZero_(row[index.followers]);
      const medianViews = numberOrZero_(row[index.medianviews]);
      const rateCardLink = index.ratecardlink === undefined
        ? ''
        : safeHttpsUrl_(row[index.ratecardlink]);
      const featured = index.featured === undefined
        ? false
        : isTrue_(row[index.featured]);

      // Require a stable ID, name, and valid public creator URL.
      if (!id || !name || !url) return null;

      return {
        id,
        name,
        url,
        niche,
        language,
        followers,
        medianViews,
        ratio: followers > 0
          ? Math.round((medianViews / followers) * 100)
          : 0,
        rateCardLink,
        featured
      };
    })
    .filter(Boolean);

  return jsonOutput_({ data: creators, updatedAt: new Date().toISOString() });
}

function normalizeHeader_(value) {
  return String(value || '').trim().toLowerCase().replace(/\s+/g, '');
}

function isTrue_(value) {
  if (value === true) return true;
  const normalized = String(value || '').trim().toLowerCase();
  return normalized === 'true' || normalized === 'yes' || normalized === '1';
}

function numberOrZero_(value) {
  const number = Number(value);
  return Number.isFinite(number) && number >= 0 ? number : 0;
}

function safeHttpsUrl_(value) {
  const text = String(value || '').trim();
  if (!text || !/^https:\/\/[^\s]+$/i.test(text)) return '';
  return text;
}

function jsonOutput_(payload) {
  return ContentService
    .createTextOutput(JSON.stringify(payload))
    .setMimeType(ContentService.MimeType.JSON);
}
```

The Apps Script helper checks for an HTTPS URL with no whitespace; the Next.js route performs stricter URL parsing before returning the data to the browser. Staff should still verify that each link belongs to the intended creator or approved rate-card destination before setting `published = TRUE`.

Deploy through **Deploy → New deployment → Web app**, choose execution as the owner only when this is intentional, and restrict access according to the use case. A public site needs anonymous reading only for the curated public dataset; it does not need access to internal CRM fields. Test both the deployment URL and a row marked `published = FALSE`. Google’s official instructions are available in the [Apps Script web apps guide](https://developers.google.com/apps-script/guides/web).

### 7.4 Why not fetch Apps Script directly from browser code?

A server-side route provides a same-origin URL for the React app, validation, consistent error responses, and caching. Browser-direct fetching from Apps Script may run into cross-origin/redirect behavior. More importantly, **a proxy does not make sensitive public data private**: the Apps Script endpoint itself must only emit the public allowlist.

### 7.5 Next.js route handler (`src/app/api/creators/route.ts`)

Set `GOOGLE_APPS_SCRIPT_URL` in the server environment. Do not add the endpoint as a `NEXT_PUBLIC_*` variable unless you intentionally want it bundled into the client. The Apps Script URL is not a true secret if the web app is publicly reachable, so endpoint secrecy is not the security boundary; the allowlisted dataset is.

```ts
import { NextResponse } from 'next/server';

export const runtime = 'nodejs';

type PublicCreator = {
  id: string;
  name: string;
  url: string;
  niche: string;
  language: string;
  followers: number;
  medianViews: number;
  ratio: number;
  rateCardLink?: string;
  featured: boolean;
};

type JsonRecord = Record<string, unknown>;

function isRecord(value: unknown): value is JsonRecord {
  return typeof value === 'object' && value !== null && !Array.isArray(value);
}

function readText(value: unknown, fallback = ''): string {
  return typeof value === 'string' ? value.trim() : fallback;
}

function readNonNegativeNumber(value: unknown): number {
  const number = typeof value === 'number' ? value : Number(value);
  return Number.isFinite(number) && number >= 0 ? number : 0;
}

function readHttpsUrl(value: unknown): string | undefined {
  const text = readText(value);
  if (!text) return undefined;
  try {
    const url = new URL(text);
    return url.protocol === 'https:' ? url.toString() : undefined;
  } catch {
    return undefined;
  }
}

function toPublicCreator(value: unknown): PublicCreator | null {
  if (!isRecord(value)) return null;

  const id = readText(value.id);
  const name = readText(value.name);
  const url = readHttpsUrl(value.url);
  if (!id || !name || !url) return null;

  const followers = readNonNegativeNumber(value.followers);
  const medianViews = readNonNegativeNumber(value.medianViews);
  const rateCardLink = readHttpsUrl(value.rateCardLink);

  return {
    id,
    name,
    url,
    niche: readText(value.niche, 'Other') || 'Other',
    language: readText(value.language),
    followers,
    medianViews,
    ratio: followers > 0 ? Math.round((medianViews / followers) * 100) : 0,
    ...(rateCardLink ? { rateCardLink } : {}),
    featured: value.featured === true,
  };
}

export async function GET() {
  const endpoint = process.env.GOOGLE_APPS_SCRIPT_URL;
  if (!endpoint) {
    return NextResponse.json(
      { error: 'Creator data is not configured.' },
      { status: 503 },
    );
  }

  try {
    const response = await fetch(endpoint, { next: { revalidate: 300 } });
    if (!response.ok) {
      throw new Error(`Upstream creator endpoint returned ${response.status}`);
    }

    const payload: unknown = await response.json();
    const rawRows = Array.isArray(payload)
      ? payload
      : isRecord(payload) && Array.isArray(payload.data)
        ? payload.data
        : null;

    if (!rawRows) {
      return NextResponse.json(
        { error: 'Creator data format is invalid.' },
        { status: 502 },
      );
    }

    const creators = rawRows
      .map(toPublicCreator)
      .filter((creator): creator is PublicCreator => creator !== null);

    return NextResponse.json(creators, {
      headers: {
        'Cache-Control': 'public, s-maxage=300, stale-while-revalidate=600',
      },
    });
  } catch (error) {
    console.error('Creator data fetch failed:', error);
    return NextResponse.json(
      { error: 'Creator data is temporarily unavailable.' },
      { status: 502 },
    );
  }
}
```

The route returns only the fields explicitly declared in `PublicCreator`, even if an upstream source accidentally includes extra properties. Keep errors generic in the public response; detailed diagnostics belong in server logs.

